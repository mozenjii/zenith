# Theme Brief

<agent_note>
This document uses YAML front matter, pseudo-XML sections, fenced schemas, and {{placeholders}} so an implementation agent can parse it safely. Do not expose private reasoning. Any <thought> block is a planning placeholder, not user-visible chain of thought.

<theme_name>
Bay Area Signal Map
</theme_name>

<elevator_pitch>
An immersive startup-style map where each Bay Area location represents a different signal about {{user_name}} as a computer science builder: what he shipped, how he thinks, what systems he built, where his technical judgment shows, and what kind of startup team he wants to join.
</elevator_pitch>

<one_sentence_version>
A Bay Area-inspired intelligence map of my proof-of-work, mapped by signal instead of listed like a resume.
</one_sentence_version>

<why_this_is_unique>
Most CS portfolios show a hero section, skills grid, projects, resume, and contact form. This theme turns the portfolio into an evaluative product experience. Recruiters can quickly see fit. Founders can see shipping ability and judgment. VC-style viewers can scan signals, traction, risk, and ambition.
</why_this_is_unique>

<audience_psychology>

<founders>
Founders care about speed, ownership, clarity, ability to handle ambiguity, and whether a person can build without needing perfect instructions.
</founders>

<startup_recruiters>
Recruiters care about skills, proof, resume access, quick scan value, polished communication, and whether projects map to real job needs.
</startup_recruiters>

<engineers>
Engineers care about architecture, code quality, tradeoffs, technical clarity, debugging ability, and whether projects are real or superficial.
</engineers>

<vc_style_viewers>
VC-style viewers care about signal density: traction, narrative, market awareness, technical leverage, and founder-like judgment.
</vc_style_viewers>

</audience_psychology>

<bay_area_metaphor_system>

| Bay Area Node | Portfolio Meaning | Content Type |
|---|---|---|
| Mission District | Experiments, prototypes, hackathons | early builds, scrappy demos |
| SoMa | Startup-style shipped systems | full-stack projects, SaaS-like builds |
| Financial District | Metrics and proof | GitHub stats, project KPIs, outcomes |
| Palo Alto | Builder thesis and ambition | career memo, future direction |
| Menlo Park / Sand Hill Road | VC-style diligence | case studies, market thinking, risk/tradeoff sections |
| Mountain View | AI/data/technical depth | ML, data, algorithms, AI projects |
| Cupertino | Product polish | UI/UX, design systems, user experience |
| Berkeley | Academic foundations | CS fundamentals, research-style learning, coursework |
| Oakland | Grit/debugging/execution | hard bugs, messy systems, resilience |

</bay_area_metaphor_system>

<theme_feel>

- Premium, not flashy.
- Foggy, not neon cyberpunk.
- Startup dashboard, not tourist guide.
- Signal intelligence, not travel map.
- Interactive but fast.
- Data-driven but human.

</theme_feel>

<anti_patterns>

- Do not use random SF tourist photos as the main design.
- Do not use Apple/Google logos unless legally safe and directly relevant.
- Do not copy official BART maps; create a BART-inspired transit-line visual system instead.
- Do not overuse slang like “disrupt,” “unicorn,” or “10x.”
- Do not fake startup traction.
- Do not make every section animated; the site must remain usable.

</anti_patterns>

<success_criteria>

- A founder should think: “This person understands product and shipping.”
- A recruiter should think: “I can evaluate this quickly.”
- An engineer should think: “There is real technical work here.”
- A VC-style viewer should think: “The narrative and signal density are unusually strong for a student portfolio.”

</success_criteria>
